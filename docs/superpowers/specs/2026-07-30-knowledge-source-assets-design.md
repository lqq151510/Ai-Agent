# 本机资料源闭环设计

## 目标

让 Knowledge Desk 在本机可靠保留已导入资料的原件，并从一个受控资料夹自动收集新文件。功能仅服务本机数据；不会上传文件、暴露绝对路径或改动用户原目录。

## 边界

- Electron main 是唯一可接触真实文件路径、受管原件目录和监听配置的层。
- 后端只保存不透明的 asset ID、显示文件名、媒体类型、字节数、哈希和可用状态；不保存本机路径或文件内容。
- Renderer 只接收安全元数据和 opaque ID；打开、定位、扫描和配置操作均经专用 IPC。
- 仅处理普通 `.pdf`、`.md`、`.markdown`、`.txt`、`.html`、`.htm` 文件，单文件不超过 20 MiB。

## 受管原件

主进程将已验证字节先写入 userData 下的私有 staging，再以 `0600` 文件权限和原子 rename 移入受管根目录。后端创建的 asset 先处于 `pending`，成功落盘后变为 `available`；崩溃恢复保留 pending journal 并在下一次启动时重新收敛，绝不读取或修改源目录。

详情页只显示“已保存 / 缺失 / 未托管”以及“打开原件”“在 Finder 中显示”操作。JSON 备份只含知识正文与安全元数据，不打包二进制原件；恢复后的 asset 以缺失状态表达，不能伪造可打开原件。

## 受控资料夹

v1 允许至多五个非递归目录。目录真实路径及 scan cursor 仅保存在主进程的私有状态文件；界面只显示用户可见标签、状态、时间和统计。目录选择后会 realpath 校验，拒绝受管数据目录、符号链接、隐藏文件、目录和超限文件。

`fs.watch` 只用于提示扫描。启动扫描和固定周期扫描保证最终一致性；每个候选经历 debounce、两次 stat 稳定检查、受限读取和 SHA-256 复核，再进入串行导入队列。内容相同由现有数据库哈希去重；内容变更导入为新的不可变快照；源文件删除不影响已收录资料。

## 验收

1. 手动导入后删除源文件，仍能通过详情页打开受管原件。
2. 稳定的新文件只导入一次；重复内容跳过；写入中的文件等待稳定。
3. 重启后 watch 配置和 pending 操作能恢复。
4. API、IPC、UI 和错误文案不包含绝对路径、相对存储路径或内容哈希。
5. 停用或移除资料夹只停止观察，不删除用户资料夹或受管原件。

## 非目标

不做云同步、递归全盘扫描、双向同步、源文件删除传播、二进制备份包、RAG/向量库或发行链路改动。
